User guide

Weekly retailer data-collection anomaly check — end-to-end workflow.

Weekly workflow

1
Download the scorecard exports. Export the Global Scorecard (Two Levels) for each business unit. Keep the business-unit keyword from your config (any case) in the filename — the tool reads the business unit from it. Both .xlsx and .json exports work.
2
Bulk upload. Select all three files at once, or drag them into the drop zone together. The three slots turn green as each business unit is recognised. Re-uploading the same business unit replaces the previous file.
3
Set the thresholds. Each module has its own threshold in the Thresholds by module panel — Availability 10 pts, Content / Search / Ratings / Reviews 5 pts by default. Type a new value to override it; the cell is tagged custom, the check re-runs instantly and the value is remembered. Reset to recommended restores the defaults.
4
Review the summary. Every retailer × module combination is listed. Set the Severity filter to Critical only to get the escalation list; leave it on All to audit the full dataset.
5
Export & escalate. Download the styled Excel file, then open the Customer Issue Tracker and filter by the Account ID from the export.

How the change is calculated

Only absolute change is used — the plain difference between the two scores, expressed in percentage points:

Change = Current score − PREVIOUS score (P1)
Example: Content 92.0% → 82.0% gives a change of −10.0 pts, which breaches the 5-point Content threshold.

PREVIOUS is always the P1 column (last period). P2 columns are ignored, even when the export contains three periods. If a retailer has no P1 score, it is not compared against P2 — it is shown as Normal (no PREVIOUS score). Only headers named exactly <Module> (P1) are read as PREVIOUS.

The Threshold column shows the value applied to each row; the Excel export includes a Thresholds sheet recording the settings used.

Account ID

The account registry is not stored in this site. It lives in your private config.json, which you load once via ⚙ Workspace config; it is kept only in your browser (localStorage). Each Country × Business unit resolves to one account; an optional language tag (l) splits markets such as Belgium Dutch / French. Switch between primary and alternate ID in the settings panel.

Excel export

Tick the Modules to export chips above the KPIs to choose which modules go into the file (Ratings and Reviews are off by default; your choice is remembered in this browser). The export mirrors whatever is on screen after filtering, with a coloured header row, frozen panes, auto-filter, red highlighting on Critical rows and a second Summary sheet that counts issues by Board region → Region → Country → Retailer.

Jira blockers

Click Connect Jira, enter the base URL and Personal Access Token, then Load / refresh Jira tickets. Each Critical row is matched to open tickets like this:

StepRule
1 · AccountThe Jira Account field (numeric account IDs, e.g. 1001 1002) must contain the row's account. Alternate IDs are also accepted.
2 · Retailer keywordBoth names are reduced to a keyword: noise words (www, shop, com, co, au, in, pvt, ltd, infocom, android, app, country codes …) are dropped and the first remaining word is the keyword — Amazon Android Example Pvt Ltd → amazon, Shop.Coles.Com.Au → coles, Flipkart.Com → flipkart. The keyword is looked for in the Retailer field, domains in the summary (amazon.in$android), labels / components, and the summary words.
3 · PlatformNames containing android / $android / app are APP; everything else is WEB. An app row only matches app tickets, a web row only web tickets.
4 · ModuleRead from the summary / components / labels (Search, Content, Availability, Ratings, Reviews; RR = both). Pricing / Assortment tickets are matched to Availability. orange = same module, grey = same retailer, other module.
Open onlyA ticket is closed only when its status is Resolved or Closed. The Resolution field is ignored.

If no ticket matches, the reason is shown under ⚠ No blocker (no open ticket for the account / ticket exists but on the other platform / no ticket mentions the keyword). If Jira can't be reached, open rows from the uploaded tracker are used as dashed Tracker chips.

Browser security (CORS). This page runs locally, so Jira must allow requests from the browser. If you see a CORS / "Failed to fetch" error, use the proxy field or Import Jira export: run the same JQL in Jira → Export → CSV (all fields). The tool then works exactly the same, offline.

Troubleshooting

  • File shows "no Country / Retailer rows found" — the export must contain the First Level and Second Level columns. Re-export as Two Levels.
  • Business unit shows "Unknown" — the filename does not contain any business-unit keyword from your config. Rename the file or edit businessUnits[].match.
  • Account ID is blank — the country / unit is not in your registry. Add it to accounts in your private config.json and reload it.
